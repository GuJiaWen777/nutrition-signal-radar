# 在单一数据库中按监测期次隔离选题状态

## 背景

工作台需要每周重复使用，同时保留长期来源资料和历史选题状态。为每一期复制整库会造成文章重复、跨期去重困难和备份碎片；继续使用一个没有期次边界的全局看板，则会混淆不同选题会的状态。

## 决定

- 来源账号和来源文章在一个 SQLite 数据库中长期积累并全局去重。
- `monitoring_cycles` 表示一次人工审阅窗口；文章通过关联表进入本期或作为上下文，主题簇及下游信号、候选和选题包归属于一个期次。
- 同一数据库只允许一个开放期次。关闭后该期次只读；下一期创建空白工作区，第一版不复制上期主题，也不提供重新打开。
- 本期选题归档是人工触发的版本化 Markdown 快照，每次写入新的 `vNNN` 目录并保留选题快照、已有选题包、清单与校验值；它不替代数据库，也不生成行业周报、深度研究稿或最终文章，不触发研究或发布。

## 结果

跨期可以复用和去重来源文章，又不会混合人工选题状态；历史期次可稳定查看和归档。代价是主题簇目前按期独立生成，跨期“同一长期主题”的自动串联留到后续单独实现。
