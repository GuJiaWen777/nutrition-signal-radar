# 每周横向信号快报与纵向深度研究双分支

## 背景

需求基线最初把“营养健康行业信号周报”定义为选题与研究完成后的未来产物，并明确当前工作台不生成该产物；本周节奏只导出“本期选题归档”。用户后续明确的产品设计是：

```text
RedFox 文章 → 主题聚合 → 行业信号
  ├─ 本周信号快报：横向扫描、周度输出
  └─ 人工确认选题 → 深度研究报告：纵向验证、形成高价值文章
```

即行业信号同时向下游分叉为“周度横向扫描”和“经人工确认的纵向深度研究”两条路径。把横向快报并入周报最终产物会让未核实信号过早获得“周报”名义，而完全不提供周度输出又会失去横向发现的价值。

## 决定

- 新增“本周信号快报”：由操作者在本地工作台显式触发的、只读的版本化 Markdown 草稿，按监测期次汇总经过生成的活跃行业信号，并按候选选题辅助分、文章量和时效排序，默认最多展示 8 条，每条附带公众号发现线索与待补证标记。
- 快报状态固定为 `draft_for_human_review`。它不核实事实、不改变任何选题或研究状态、不创建研究任务、不调用 LLM、不写入或发布微信公众号；导出只新增 `exports/weekly-signal-briefs/<cycle>/vNNN/` 目录，旧版本不覆盖，数据库只写入导出记录和期次事件。
- 快报与两个既有产物严格区分：`本期选题归档`只记录选题看板与选题包；未来的“营养健康行业信号周报”仍是选题与研究完成后的可发布汇总产物。快报不是周报、不是深度研究报告、也不是最终文章。
- 纵向分支维持全部人工门禁：确认选题包 → 创建并人工确认研究任务书 → 手动或显式开启的自动启动 → 深度研究稿人工审阅 → 最终文章确认；两条分支互不自动推进对方。

## 结果

行业信号既能形成每周可审阅的横向扫描，又不会因为周度输出而绕过选题确认、研究任务书或稿件审阅门禁。“营养健康行业信号周报”继续保留为未来下游产物，本快报只是它之前的可编辑工作草稿之一。
