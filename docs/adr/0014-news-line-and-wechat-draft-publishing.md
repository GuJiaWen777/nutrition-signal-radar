# 资讯自动线「营养健康行业资讯」与微信草稿箱发布

## 背景

`docs/DSA自动化文章需求.docx` 提出 EarlyData 公众号的第二条内容线：与数据洞察内容完全独立的《营养健康行业资讯》，每日自动抓取白名单信源、筛选分级、AI 摘要成文、生成排版 HTML 与封面图，并自动进入公众号草稿箱、按接口权限定时发布。用户于 2026-08-31 修订 AGENTS.md：解除"不得添加微信发布/草稿箱路径"的禁令（群发仍禁止），并批准只读参考 `D:\Earlydata\SentimentTracker` 的微信实现（其 `src/earlydata_weekly_publisher/pipeline.py` 已有 token、永久素材、`draft/add` 完整链路）。

此前本仓库的全部产物（信号快报、可发布周报文章、深度研究稿）都以公众号监测材料为输入、以人工确认为发布前最后一道门禁；资讯线在信源、输入与人工介入程度上都与之不同，需要单独定界。

## 决定

**内容线定位**

- 新增独立"资讯内容线"，产物为公众号文章《营养健康行业资讯｜XXXX》（栏目：01 政策监管、02 品牌与财报、03 展会与产业活动；单篇 3–5 条、全文 1000–1800 字）。它与"本周信号快报""可发布周报文章""每日快报（P3-01）"互不替代：资讯线的输入是白名单直采信源，不使用 EarlyData 电商数据，也不以行业信号管线为主输入。
- 资讯线遵守需求文档的内容红线：不转载或改写大段原文、不使用夸张表述、不把征求意见稿写成正式政策、不把品牌新闻写成行业事实或趋势结论、不对保健食品作疾病治疗表述。

**信源与门禁**

- 新增资讯白名单注册（独立于"重点网站"研究优先清单的语义：它是抓取范围的严格白名单）：按政策监管、法定披露、品牌官方、展会主办方、科研行业组织五类登记约 30 个种子信源，默认全部停用；操作者人工确认名单并显式启用后进入抓取范围。每源记录抓取入口、解析配置版本与默认 P0–P3 建议级；启用/停用与配置变更写审计事件（模式同现有来源注册表）。
- 白名单首次确认是资讯线唯一固定的内容人工节点；此后"采集 → 筛选 → 成文 → 质检 → 推送草稿箱"每日免人工运行。既有选题、研究、归档人工门禁不受影响。

**采集架构**

- 主路径为直采适配器：HTTP 抓取列表页、公开接口或 RSS，每源一份解析配置；识别过去 24 小时新增，复用归一化文章契约与幂等去重；脱敏原始响应存 `var/raw/sites/YYYY-MM-DD/`；单源失败不影响其他源。
- Exa 搜索作兜底与每周一"过去 7 天重要遗漏"补捞，结果必须过滤回白名单域名；程序化调用需新增 `EXA_API_KEY`（仅经 `.env`）。pi 的 `fetch_content` 仅作单条正文补全的兜底（列表页缺正文或反爬场景），不作为每日批量采集器；资讯成文不使用 pi 联网写作。
- LLM 不参与采集与筛选层；筛选、P0–P3 分级与拦截规则用确定性规则实现，保证每条入选与落选都有可追溯理由。
- 抓取频率：每日 08:30 抓取过去 24 小时；高优先级来源 2–4 小时一次作为二期；调度由 Windows 任务计划程序调用 CLI 完成（不引入守护进程），任务命令行显式包含 `--live`（一次性人工配置即显式授权），手工调试仍受 `--live` 保护。

**成文与质检**

- 每条入选资讯由配置的分析后端（DeepSeek，OpenAI 兼容协议）按 JSON 契约生成固定字段：分类标签、原始标题、发布日期、发布机构、120–180 字中文摘要、"对行业意味着什么"（仅限基于原文的客观说明）、原文链接。模型只见已抓取内容，不得补充未出现的事实；输出经本地字段校验加需求文档拦截规则（无链接/无日期/无发布方、来源不明转载、预测写成事实、征求意见稿写成正式政策、无依据数据与金额、疾病治疗类表述），不合格条目不入文并记入质检日志。
- 文章由确定性模板组装并自动质检（条数、字数、栏目齐备、来源字段完整、AI 套话词表）；每日入选不足 2 条时不强行生成日报，自动转为"本周营养健康行业资讯"周报形态。
- **本地产物先行（2026-09-01 用户确认）**：成稿先落本地版本化产物——公众号正文 HTML（内联样式、可直接粘贴公众号编辑器）、Markdown 母稿、资讯源数据表（标题/来源/日期/URL/抓取时间/分类/摘要/是否入选）、质检日志与 manifest，不覆盖旧版本。封面 PNG（P4-05）随后补充。
- 微信草稿箱推送是独立的后续切片（P4-06）：在凭据配置、接口权限确认并获操作者批准后单独接入；接入前，资讯线的每日交付物就是本地 HTML 与配套文件。

**排版与封面**

- 公众号正文 HTML 按需求文档第六节规格自建模板：全内联样式、`<section>` 结构、Noto Sans SC 与既定品牌色（#173B66 / #2F6CAE / #72BF44 / #2B3545 / #718096 / #F1F6FC）；推送前执行排版规范校验。不复制 SentimentTracker 的视觉样式与代码文件，只参考其技术做法（内联样式、发布前 HTML 校验、正文图片先上传再替换链接）。
- 封面为 1800×766 PNG，**HTML 模板 + 无头浏览器截图为主、PIL 程序化渲染兜底**（2026-09-01 用户确认）：封面版式固化为入库的版本化模板 `templates/cover.html`（改模板=改代码，保证"尺寸、字体、Logo、颜色完全统一"），程序只填入标题、日期与 Logo 字段后用本机 Edge/Chrome 无头截图；浏览器不可用或截图异常时自动回退 PIL 渲染。主视觉文案固定不变；EarlyData 官方 Logo 原图由操作者提供（`var/assets/earlydata-logo.png`），不自动抓取第三方 Logo。不允许运行时让 LLM 即兴生成封面。

**发布**

- 新增 `wechat_gateway.py`：实现 access token 获取、封面永久素材上传（`material/add_material`）、正文图片上传（`media/uploadimg`）与草稿箱写入（`draft/add`），参考 SentimentTracker `pipeline.py` 的既有链路；凭据仅经 `.env`（`WECHAT_APP_ID` / `WECHAT_APP_SECRET`），不写入代码、数据库、日志或版本库；测试全程 mock，不发起真实微信请求。
- `news build --live` 生成当日成稿的本地版本化产物（HTML/Markdown/源数据表/质检日志）；微信草稿箱推送（P4-06）是**人工显式动作**：`news publish` 必须同时携带 `--live`（外呼确认）与 `--confirm`（人工复查本地产物后的决策确认）两个门禁，缺少任一即拒绝执行；每日调度链只包含 fetch → select → build，绝不含 publish（2026-09-01 用户确认）。`freepublish` 定时发布取决于公众号接口权限，作为二期决策。发布目标账号以配置的 AppID 为准（预期为「EarlyData电商大数据」，"营养健康行业资讯"是系列栏目名）。
- 群发（mass-send）路径在任何阶段都被禁止。

## 结果

本仓库在资讯自动线范围内获得"自动进草稿箱/定时发布"的能力，其余产物线的人工复制发布边界不变；白名单首次人工确认后，资讯线按"每日无需人工搜集、摘录、排版"的验收方向运行。代价与风险：政府与交易所站点改版或反爬会使个别解析配置失效，需要原始响应存档、失败隔离与来源健康提示来暴露；微信接口依赖已认证服务号的接口权限与 IP 白名单；新增 `EXA_API_KEY` 与微信凭据两类外部凭据的管理责任。
