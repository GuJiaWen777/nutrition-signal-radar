# 可发布周报文章与横向快报分离（人工确认后发布）

## 背景

用户反馈“本周信号快报”目前内容太粗糙，目标应是可直接作为独立微信公众号文章发出的成品；正文中不能出现“待补证”等内部工作标记。参考输出是两篇已发布的《营养保健行业周报》：

- 《营养保健行业周报|蚂蚁28%入股薄荷、40元假洋牌卖300元》
- 《营养保健行业周报|功能食品峰会落幕，政策监管升级，企业全球化布局加速》

参考文体按主题分节（例如“一、资本市场”“二、AI+健康”“三、原料创新”“四、监管趋严”），每条以“日期 + 主体 + 事件 + 关键数据 + 影响/判断”呈现，面向行业决策者。

## 决定

- 横向信号快报保留为内部审阅产物：`weekly_signal_briefs` 不变，正文可继续出现“待补证”等内部标记。
- 新增 `weekly_articles` 表与 `exports/weekly-articles/<cycle>/vNNN/` 目录，作为“可发布周报文章”的独立版本序列；它与快报各自从 v001 开始，互不占用版本号。
- 文章由 pi 公开网页 Agent 生成：服务先取本期行业信号快照（信号、事件、共识、公众号链接），构造参考文体写作任务，要求 Agent 用 `web_search` / `fetch_content` 核实关键事实，并按 JSON 契约返回标题、导语、正文、内部编辑备注与来源。
- 标题与正文执行硬性发布契约：出现“待补证”“公众号发现线索”“内部状态”“人工审阅”“证据状态”“草稿”“未核实”等内部标记即拒绝入库；不确定性只写入 `manifest.json` 的 `editor_notes` 与 `sources`，供人工复核，不进入可发布文本。
- 文章状态为 `draft_for_human_review`，只能由操作者显式 `confirm` 定稿（写入 `confirmed_at`）；已定稿可 `reopen` 回到待编辑。确认不等于授权发布，系统不包含微信公众号草稿箱写入或群发路径。
- 看板“本周快报”标签页内部分为“信号快报 / 可发布文章”两种视图；文章视图展示标题、正文、状态与确认入口，仍与“研究与成稿”标签分离。
- 生成文章必须显式 `weekly article generate --live`，看板与默认命令不触发 pi 调用。

## 结果

横向快报继续承担未核实发现职能，周报文章承担可直接发布成品职能；两者同属周度输出但生命周期分离。“待补证”等内部状态只存在于数据库、清单与编辑备注，不会泄漏进发布正文；发布前的最后一步仍是人工确认。
