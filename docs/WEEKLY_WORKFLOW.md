# 周度操作指引（WEEKLY WORKFLOW）

本文档说明本工作台的监测期次机制和每周例行操作。工作台地址 `http://127.0.0.1:8765`。

## 1. 期次机制（先记住三条规则）

1. **同一时间只有一个开放期次**（数据库层约束）。要新建下一期，必须先关闭当前期次。
2. **关闭不可逆**：期次关闭后所有内容只读（信号、选题、选题包、快报、文章都不能再编辑），本版本不提供重新打开。
3. **所有历史期次都留在下拉框里**，随时可以切换查看；顶部「监测期次」区域选择后，各标签页都切换到该期次的数据。

每个期次独立持有：期次内文章（按 `published_at` 落在期次起止日期内才算 `in_period`）、主题簇 / 行业信号 / 候选选题、信号快报（vNNN）、可发布文章（vNNN）。

## 2. 每周例行流程

按顺序执行；第 1、2 步是数据入口（顺序不能反），第 3~6 步是产出。

1. **新建周次（先定数据范围）**：顶部「新建下一期」，表单已按“最新期次结束日 + 1 天 ~ + 7 天”预填（周一~周日），确认即可。**期次的起止日期就是本期的数据范围**。
   - 周中已有开放周次在收数据时，跳过这一步，直接用当前期次。

2. **同步取数**：顶部「获取文章」→ 选择日期区间（默认自动填当前期次的起止日期）→ 确认后按该区间从 RedFox 拉取启用公众号的文章，再按发布日期自动归入**当前开放期次**：落在期次起止范围内的算 `in_period`（参与信号），范围外算 `context`（不参与信号）。CLI 等价命令：`sync --live --lookback-days N`（按最近 N 天取数）。

   - 顺序很重要：**必须先有开放期次再同步**（没有开放期次 sync 会直接报错）；如果先同步、后建期次，新周文章会先被标成上一期的 `context`，建完期次后需要再同步一次才会归位。
   - 周中随时可以再同步（如 `--lookback-days 3`），新文章实时进入当前周次；新周开始时的首次同步建议 `--lookback-days 8` 覆盖整周。
   - sync 没有“按日期区间取数”的参数；要回看更早历史只能加大 `--lookback-days`（之前的 30 天回看就是这样做的）。

3. **（可选）DeepSeek 解读**：让规则信号带上来源共识、分歧、业务含义等解读字段（只对当前开放期次生效；真实计费，必须显式 `--live`）：

   ```powershell
   .\.venv\Scripts\nutrition-radar.exe signals analyze --live --max-signals 30
   ```

4. **（可选）人工排序**：行业信号标签页每张卡右下角有「文章序」输入框——数字越小越靠前，留空恢复规则排序。设了文章序的信号排在最前，**直接决定信号快报的展示顺序和可发布文章的取材顺序与标题钩子焦点**（规则重建不会覆盖人工排序）。

5. **生成信号快报**：标签页「本周快报」左列点「生成信号快报」（规则生成、免费、即时）。生成后可编辑、删除、导出 MD。已经有关闭期次想重新导出的，可用 CLI `weekly brief --cycle <slug>`。

6. **生成可发布文章**：「本周快报」右列点「生成可发布文章」（调用 pi 联网检索，真实计费，约几分钟）。生成后停在「待人工审阅」，人工「确认定稿」后复制到公众号发布；需要修改先「编辑」或退回。
   - 已关闭的历史周次在界面上没有生成按钮，可用 CLI 补生成：

     ```powershell
     .\.venv\Scripts\nutrition-radar.exe weekly article generate --cycle <slug> --live --json
     ```

7. **关闭周次**：本周工作完成、要开始下一周时，点顶部「关闭本期」。关闭后该周次变只读历史；随后回到第 1 步开始新一周。

## 3. 历史周次

- 下拉框选择历史期次，所有标签页以只读方式展示该期次内容；快报和文章的「导出 MD 文件」仍可用。
- 关闭期次不能再编辑、不能再跑 DeepSeek 解读（`signals analyze` 只接受开放期次）。
- 每周的可发布文章独立版本号（v001 起），互不影响。

## 4. 一次性工具：把长周期拆成周

当前 30 天演练期次已通过该工具拆分为 4 个周次 + 一个空白新周次（见第 5 节）。以后若再遇到跨多周的长期次，可以用：

```powershell
.\.venv\Scripts\python.exe scripts/split_cycle_into_weeks.py --db var/radar.sqlite3 --dry-run   # 先看计划
.\.venv\Scripts\python.exe scripts/split_cycle_into_weeks.py --db var/radar.sqlite3 --yes       # 执行
```

行为：关闭源期次（不可逆）→ 依次创建 4 个周次（各自重建规则信号并导出信号快报，全部关闭）→ 新建一个空白周次并保持开放。周界默认按"以 08-10~08-16 为一周往前推"，首周吸收期初不足 7 天的头部数据；周界和后续周期次范围可在脚本常量中调整。
